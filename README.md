# Mery Gemini Task Macro

Mery Gemini Task Macro は、Windows 向けテキストエディタ **Mery** 上で、Markdown の `TASKS.md` / `LOG.md` / `OUTBOX.md` などを使って TODO 管理を行うためのマクロ集です。

反転選択したテキストやカーソル行を、メニューから選んで `TASKS.md` に取り込んだり、`LOG.md` に記録したり、Gemini API で整理案を作ったりできます。でも、gemini設定なしでも十分使えるようにしたいです。

現在まだ開発中です。作者の環境で動作確認している段階のため、安定版ではありません。

## 2026-10-08 の更新：目標管理とメニュー導線

作業メニューの「年・月・週の目標と期限を管理」から `GOALS.md` を開き、年目標の下に複数の月目標、週目標、行動TODOを階層化できます。ウィザードで入力を検証し、誤りがあれば同じ入力へ戻ります。生成後も通常のMarkdownとして直接編集できます。TODOには期限日だけを設定でき、必要な場合だけ時刻を追加します。目標は `TASKS.md` / `LOG.md` と独立して管理します。詳しくは [目標管理](README_目標管理.md) を参照してください。

### TODOメニューを「マクロ」内に置く理由

Meryでは「ファイル」「編集」などが並ぶメニューバーに、独自のトップレベルメニューを追加する標準機能が確認できません。そのため、このプロジェクトでは独立した「TODO」見出しを追加せず、Mery標準の「マクロ」メニューから `Mery_作業メニュー.js` を実行する構成にしています。Mery本体のメニューバー拡張が可能になった場合は、改めて検討します。

作業メニューをボタンから使う場合は、親マクロの「作業メニューのボタン追加案内」を開いてください。案内に従って「マクロのカスタマイズ」に親マクロを登録し、マクロバーに表示します。これはユーザーがボタンを押したときだけ実行され、Mery起動時の自動実行は行いません。

## 2026-10-05 の更新：TODOにメモ・資料を追加

TODOの直下にメモを書き、必要な本文をTXTに保存して後から開けるようになりました。画像やOneNoteから出力したPDFもTODOに関連付けられます。

| 操作 | できること |
| --- | --- |
| このTODOにメモを作る | `メモ：`と入力欄の追加、選択本文／メモ欄全体のTXT化、空のTXT作成 |
| 関連メモを開く | `notes`内のTXTをMeryの縦書きで開く。複数なら選択 |
| 資料を追加 | 画像・PDFを選び、`img`へコピーして短い表示名の参照を追加 |
| 資料を開く | カーソルのあるTODOの画像・PDFをWindowsの既定アプリで開く |
| 作業ハブのバックアップ… | 今すぐ保存、最新・月別履歴・変更一覧の表示、保存先と毎日21時の設定 |

```markdown
- [ ] 曲の構成を考える
  メモ：
    展開を整理する。
  関連メモ: [メモ1][memo-1]
  資料: [画像: 構成図][img-1]
  資料: [PDF: ノート][img-2]

[memo-1]: notes/20261005_001.txt
[img-1]: img/20261005_001.png
[img-2]: img/20261005_001.pdf
```

TODOの行か直下にカーソルを置いて実行します。`メモ：`／`メモ:`や資料の参照は手書きも可能です。TXTへ写したメモ本文は元のTODOにも残します。資料の表示には絵文字を使わず、`画像:`／`PDF:`で区別します。関連メモには本文の保存状況を示すアイコンを付ける場合がありますが、フォントによって表示されないことがあります。

メモ本文の字下げは作業メニューから手動で整形できます。開いたときにも自動で整える場合は、マクロのカスタマイズで「ファイルを開いた時」イベントに `Mery_TASKSメモ欄のインデントを整える.js` を登録します。作業ハブの `TASKS.md` 以外では何もせず、変更時だけバックアップを作成して保存します。

短い参照はMery本文でクリックして開く形式ではありません。「関連メモを開く」「資料を開く」を使います。別の文書にTODOをコピーするときは、文書末尾の参照定義も一緒にコピーしてください。Google同期、Geminiの再整理、LOGへの移動時のメモ・資料参照保持は未対応です。ファイル名などは自動生成です。

詳しくは [メモ連携](README_メモ連携.md) と [資料連携](README_資料連携.md) を参照してください。

### 補助スクリプトの配置

画像・PDFの選択とバックアップにはWindows PowerShellを使います。`hub-tools`の次のファイルを、マクロのフォルダではなく作業ハブの直下（標準: `C:\Projects\ai-work-hub`）へコピーしてください。

```text
pick-asset.ps1
backup.ps1
setup-backup.ps1
backup.json
README_バックアップ.md
```

`backup.json`の配布版は保存先未設定です。すでに設定したファイルは上書きしないでください。メニューから保存先を設定すると、毎日21時の定期実行を登録します。バックアップは全ての`.md`、メモ、資料、マクロを含み、「最新」と「履歴/YYYY-MM」に保存し、変更ファイル名を一覧に記録します。過去の履歴は自動削除しません。詳しくは [バックアップの説明](hub-tools/README_バックアップ.md) を参照してください。

### その他の改善・検証

- 通常の「作業ハブを開く」はTASKSとLOGを表示します。COMMANDとOUTBOXは必要なときに開きます。
- 「今日やる」の並べ替えはOSの暗号学的乱数を使い、3回の各処理の前に100〜600msのランダムな待ち時間を入れます。Node.jsが必要です。
- メモと資料は模擬Mery環境で、本文保持・参照・保存失敗・取消・メニューの呼び出しを検証しました。関連メモの表示はユーザー環境で実行確認済みです。新しい資料選択と外部アプリ表示のMery実機確認は別途必要です。
- バックアップはWindows PowerShellで、日本語.mdのコピー、履歴保持、変更一覧、別の保存先を拒否する動作を検証しました。実ドライブと定期実行の運用確認は保存先設定後に行います。


## 2026-10-03 の更新：このマクロでできること

日々のタスクと作業ログを Mery の Markdown で管理し、Gemini で整理し、Google の My Tasks / カレンダーと同期できます。

| 目的 | できること |
| --- | --- |
| 今日の作業を集める | 今日のテンプレート作成、選択範囲の取り込み、プロジェクト TODO.md の読み込み |
| 記録を整える | チェック表記の正規化、同日の重複整理、完了項目の LOG 記録、日次レビュー |
| Gemini に相談する | 選択範囲・今日のタスクの整理案、今日やるの優先度案 |
| 今日やるを見やすくする | Gemini のグループ分け案を生成し、プレビューと確認後に TASKS.md へ反映 |
| Google と連携する | TASKS.md と設定したプロジェクト TODO.md は My Tasks、LOG.md はメインカレンダーと双方向同期 |
| Google の変更を取り込む | TASKS の変更と未登録の My Tasks 項目を今日の「今日やる」へ反映。過去の未完了 TASKS も今日へ配置 |
| IDを表示しない | TASKS の同期IDを `.mery-calendar/tasks-ids.json` に保存し、Google のIDメモも同期時に整理 |

今回、文字コードの混在、同日ブロックの統合、LOG の独自見出しと記録先の日付、日本語ストリームの文字化け、Gemini 中断時の出力保護も修正しました。

Google同期はユーザー環境で実行確認されています。新しいグループ分け機能は模擬応答と文書操作のテストで検証しており、Mery 上の操作と実際の Gemini 応答の確認は別途必要です。

### 今日やるのグループ分け

作業メニューの **「今日やるをGeminiでグループ分け・反映」** から次の順に使います。

1. 「Geminiにグループ分け案を作ってもらう」で提案を生成します。
2. 「グループ案をTASKSの表示でプレビュー」で見た目を確認します。
3. 「確認したグループ案をTASKS.mdへ反映」で確認して適用します。

`グループ案.md` の JSON はグループ名・順序・所属を調整できます。T番号は提案の照合用で、TASKS.md には入りません。タスクの欠落・追加・番号重複がある提案や、生成後に TASKS が変更された場合は適用を停止します。

反映すると、例えば次のようになります。タスク名・チェック状態・同期IDは維持し、他の日付や「次にやる」などは変更しません。

```markdown
### 今日やる

#### 生活
- [ ] 買い物
- [ ] 洗濯

#### 開発
- [ ] マクロを改善する

#### 完了
- [x] メールを返信する
```

提案生成には既存の `GEMINI_API_KEY` と `call_gemini_api.js` を使います。元の文書は反映前にバックアップします。Google から同日の「今日やる」にあるタスクを更新するときは、そのグループ内の位置を保持します。

## 主な機能

- 作業ハブの `TASKS.md` / `LOG.md` を開く（`COMMAND.md` / `OUTBOX.md` は必要時に表示）
- 今日の `TASKS.md` テンプレートを作成
- 選択範囲を今日の `TASKS.md` に追加
- `TASKS.md` の完了項目を `LOG.md` に記録
- 今日の `TASKS.md` 内の重複項目を整理
- `- [ ]` / `- [x]` のチェックボックス表記を正規化
- `TODO.md` を読み込み、必要な項目を今日の `TASKS.md` に取り込み
- Gemini API を使って、選択範囲や今日の TASKS の整理案を作成

## インストール

### 1. ZIPを展開する

ダウンロードした ZIP ファイルの中身を、任意のフォルダに展開してください。

Mery のマクロディレクトリ以外でも動作する場合がありますが、通常は Mery のマクロとして登録しやすい場所に置くのがおすすめです。

### 2. 作業ハブ用フォルダを作る

標準では、以下のフォルダを使用します。

```text
C:\Projects\ai-work-hub
```

作成していない場合は、手動で作成してください。

別の場所を使いたい場合は、各マクロ内の次の定数を書き換えてください。

```js
var HUB_DIR = "C:\\Projects\\ai-work-hub";
```

### 3. Gemini APIキーを環境変数に設定する

Gemini API を使う場合は、API キーを Windows の環境変数に設定してください。

このマクロ集では、標準で次の環境変数名を使います。

```text
GEMINI_API_KEY
```

設定後、Mery や PC の再起動が必要になる場合があります。

Gemini API キーの取得・設定方法は、以下の Mery Wiki の説明を参考にしてください。

```text
https://www.haijin-boys.com/wiki/Google_Gemini_%E3%81%AB%E7%9B%B8%E8%AB%87
```

使用するモデルは `call_gemini_api.js` 内で設定しています。標準では軽量寄りのモデルを指定しています。

```js
const AI_MODEL = "models/gemini-2.5-flash-lite";
```

他のモデルを使いたい場合は、この箇所を変更してください。

### 4. Mery からマクロを実行する

まずは、次のマクロを実行してください。

```text
Mery_作業メニュー.js
```

Mery のメニューやマクロバー、ショートカットキーに登録しておくと便利です。

よく使う機能は、ショートカットキーに割り当てても構いません。

「マクロ」メニューまたはマクロバーから起動できます。ボタン登録の手順は、親マクロ内の「作業メニューのボタン追加案内」を参照してください。
また、アウトラインとアウトプットウィンドウを開いておくと便利です。

## 基本の使い方

### 作業ハブを開く

`Mery_作業メニュー.js` を実行し、次を選びます。

```text
作業ハブを開く
```

標準では、以下のようなファイルを使います。

```text
TASKS.md
LOG.md
COMMAND.md
OUTBOX.md
TODO案.md
LOG案.md
TASKS案.md
PROJECT_TODO.md
DAILY_REVIEW.md
```

### 今日のTASKSを作る

作業メニューから次を選びます。

```text
今日の開始テンプレートを挿入
```

`TASKS.md` に今日の日付のセクションが作られます。

標準形式は Markdown のチェックボックスです。

```md
- [ ] 未完了タスク
- [x] 完了タスク
```

### 選択範囲をTASKSに追加する

`OUTBOX.md`、`TASKS案.md`、`PROJECT_TODO.md`、普通のメモなどで、取り込みたい行を選択します。

その後、作業メニューから次を選びます。

```text
選択範囲を今日のTASKS欄へ追加
```

追加先を選べます。

```text
今日やる
次にやる
後で
置く
確認が必要
メモ
```

### TASKSをLOGへ記録する

完了したタスクを選択して、作業メニューから次を選びます。

```text
TASKS選択項目をLOGへ記録
```

`LOG.md` に記録され、`TASKS.md` 側は `- [x]` に正規化されます。

### TASKSを整理する

作業メニューから次を選びます。

```text
TASKS.md 今日分の重複項目を整理
```

以下をまとめて整理します。

- 同名サブ項目の統合
- `## 今日やる` / `### 今日やる` / `#### 今日やる` などの見出しレベル差の補正
- 今日分全体での重複削除
- `✓` / `済:` / 二重三重チェック表記の正規化
- `- [ ]` / `- [x]` への統一

整理前にはバックアップが作られます。

```text
C:\Projects\ai-work-hub\TASKS_backup_YYYYMMDD_HHMMSS.md
```

### プロジェクトのTODO.mdを読む

作業メニューから次を選びます。

```text
プロジェクトTODO.mdを読み込む
```

アクティブ文書の場所から上位フォルダへ向かって `TODO.md` を探し、見つかれば `PROJECT_TODO.md` に読み込み表示します。  
見つからない場合は、プロジェクトフォルダを選択できます。

元のプロジェクト `TODO.md` は自動では書き換えません。  
まずは読み込み専用です。

## チェックボックス表記について

標準は以下です。

```md
- [ ] 未完了
- [x] 完了
```

ただし、入力互換として以下も読み取ります。

```md
- タスク
- ✓ タスク
✓ タスク
済: タスク
- [ ] タスク
- [x] タスク
- [ ] [ ] タスク
- [x] [ ] タスク
```

マクロで整理・追記・LOG記録したタイミングで、基本的に `- [ ]` / `- [x]` に寄せます。

## Gemini APIを使う機能

Gemini API を使う主なマクロは以下です。

```text
Geminiタスク管理.js
Mery_TASKS今日分をGeminiで整理.js
call_gemini_api.js
```

Gemini API を使わないローカル処理だけでも、TASKS/LOG 管理の多くは利用できます。

API の無料枠やレート制限に達した場合は、エラーが出ることがあります。  
その場合は時間を置いて再実行してください。

## ファイル読み書きと中断

ファイル読み取りは UTF-8（BOMあり・なし）と、BOM付き UTF-16LE / UTF-16BE に対応します。マクロのファイル書き出し処理は UTF-8 に統一しています。Mery の保存設定で UTF-16 が使われている既存ファイルも読み取りできます。

Gemini の通信中に Shift キーで処理を中断した場合、途中の応答で OUTBOX / 整理案ファイルを更新しません。

## 回帰テスト

Node.js がある環境で、リポジトリのフォルダーから次を実行してください。

```text
node tests/run.cjs
```

日付ブロックと独自の LOG 小見出しの保持、当日への LOG 記録、文字コード、日本語のストリーム境界、中断時の出力保護を検証します。Mery の文書操作と Gemini 通信はテスト用の代替実装を使うため、Mery 上での動作確認と実 API 接続の確認は別途必要です。

## Google カレンダー同期

作業メニューの同期マクロは単一ファイルで実行できます。Node.js 24 以上、Google Calendar API / Google Tasks API、デスクトップ用OAuth認証JSONが必要です。TASKSとプロジェクトTODOはMy Tasksへ、LOGはメインカレンダーへ双方向同期します。初期設定は [Google Tasks 同期の手順](README_Google_Tasks.md)、従来のカレンダー処理は [Google Calendar の手順](README_Google_Calendar.md) を参照してください。同期IDと前回の状態は .mery-calendar に保存されるため、このフォルダーと文書をセットで保管してください。既存のTASKSカレンダー予定は残し、更新版では更新・削除しません。

同期テスト: `node --test tests/calendar.cjs`
