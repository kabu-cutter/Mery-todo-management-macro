# 年・月・週の目標とTODO期限

`Mery_作業メニュー.js` の「年・月・週の目標と期限を管理」から利用します。既存の `TASKS.md` と `LOG.md` は変更せず、目標は作業ハブ直下の `GOALS.md` に分けて保存します。

`GOALS.md` は通常のMarkdownファイルとして直接編集できます。マクロは追加・期限設定を補助するもので、ウィザードを使わずに項目を書き換えたり、チェックを付けたりして構いません。

## 目標の作り方

「目標を順番に作成（複数可）」を使うと、質問に答えるだけで年→月→週→TODOの階層をまとめて追加できます。各段階で「同じ親の下にもう1件追加しますか？」と確認するので、年間目標・月目標・週目標・TODOを複数登録できます。期限日と時間帯は任意です。途中でキャンセルすると、今回入力した分は追加されません。

1. 「目標ファイルを開く / 作成」で `GOALS.md` を開きます。
2. 「年間目標を追加」で対象年と目標を入力します。
3. 年目標の行にカーソルを置いて「選択した目標の下に追加」を実行し、月目標を作ります。
4. 月目標の行から同じ操作で週目標を作ります。
5. 週目標の行から同じ操作で行動TODOを作ります。

階層は字下げで表します。同じ親の下に子目標を複数並べる場合は、同じ字下げにします。年→月は2字、月→週は4字、週→TODOは6字です。年目標・月目標・週目標・TODOのそれぞれに複数の子項目を追加できます。子目標の期間は入力時に変更できます。週は ISO 週（例: `2026-W41`）で、月曜始まりです。

## 期限と時刻

行動TODOの期限日は任意です。時刻はさらに任意で、日付だけなら時刻入力を空欄にします。

```markdown
- [ ] 書類を提出する <!-- mery-due:2026-10-08 -->
- [ ] 面談 @09:30-10:00 <!-- mery-due:2026-10-08 -->
```

期限マーカーは既存の Google Tasks 連携でも使われている形式です。`TASKS.md` と `LOG.md` の予定日は従来どおり日付見出しから判定するため、このマクロの期限設定対象から除外しています。

編集前に同じフォルダーへタイムスタンプ付きバックアップを作ります。未保存の文書は変更せず、先に保存を促します。

## Thunderbird とローカル双方向同期

CalDAV サーバーはこのPCの `127.0.0.1` だけで待ち受けます。外部ネットワークやアカウントは使いません。データベースと同期状態は作業ハブの `.mery-calendar\goals-caldav.sqlite` に保存されます。Thunderbirdのインストールから始める場合は [導入と設定の手順](README_Thunderbird.md) を参照してください。

1. 先にMeryの「作業メニュー」で **Thunderbird カレンダーと双方向同期** を実行します。Google同期のすぐ上にあります。「目標管理」の **MeryTODO CalDAV同期（プレビュー・反映）** からも同じ処理を起動できます。ローカルサーバーがバックグラウンド起動し、初回は同期前にGOALS.mdの各目標行へ一意IDを付けます。
2. 開いた `MERYTODO_CALDAV_REPORT.md` で変更・競合・削除を確認し、確認ダイアログで初回反映します。
3. Thunderbird の「カレンダー」画面で **新しいカレンダー → ネットワーク上 → CalDAV** を選びます。
4. 場所に `http://127.0.0.1:18453/calendars/default/MeryTODO/` を入力し、名前を `MeryTODO` にします。ユーザー名とパスワードは空欄です。作成画面の「オフラインサポート」は有効のままにします（初期状態で有効）。

年間・月間・週間目標は期間予定、GOALS.md内の行動TODOとTASKS.mdのチェック項目はThunderbirdのToDoとして同期します。TASKS.mdは今日以降の日付見出しにある項目が対象で、過去の日報項目は新規同期しません。いったん同期した項目は日付が過去になっても照合を続けます。TASKS.mdのID対応は `.mery-calendar\caldav-tasks-ids.json` に保存します。GOALS.mdの年・月・週目標と行動TODOの各行は `<!--g:1-->` のような短い参照番号を持ち、同じファイル末尾の `mery-goal-id-map` に完全な128ビットIDを保存します。従来の長いIDマーカーも読み込めます。対応表がない参照番号や、IDを付けた行の複製は安全のため同期を止めます。GOALS.mdと `.mery-calendar` を一緒にバックアップしてください。

GOALS.mdの年・月・週の階層を正本として保ち、Thunderbirdからの階層変更は自動適用せず競合として報告します。片方だけの変更は反映し、両方で別の項目を編集した場合は項目単位でマージします。同じ項目を両方で変更した場合は該当フィールドと両方の値をレポートし、自動上書きしません。ThunderbirdでTASKS.mdの期限日を変えた場合は、対応する日付見出しへ項目と直下のメモ類を移動します。

GOALS.mdで項目を削除した場合、Thunderbird側が同期前のままならカレンダー項目も削除します。Thunderbird側で変更済みの項目や、子目標のある項目の削除は競合として保護します。GOALS.mdを外部エディターで変更した場合は、Meryで保存してから同期してください。反映時は必ず変更前のGOALS.mdバックアップを作成します。

同じ行動ToDoをGOALS.mdとTASKS.mdの両方に置く場合は、`.mery-calendar\goals-task-links.json` に両方の完全なIDを明示して連動できます。件名と完了状態を双方向に反映し、ThunderbirdにはGOALS.md側のIDで1件だけ表示します。TASKS.mdの日付・欄とGOALS.mdの目標階層はそれぞれ維持します。初回の対応付けではGOALS.md側の値を採用し、TASKS.md側の重複したCalDAV項目を同期プレビューに削除対象として表示します。以後、両方で異なる編集があれば上書きせず停止します。件名だけが同じ別のToDoを自動で連動することはありません。この対応表もMarkdownと一緒にバックアップしてください。

TASKS.mdに同じ件名を別の日付にも記録した場合は、ThunderbirdのToDoには最新日付の1件だけを同期します。過去の日付の行はMeryのTASKS.mdに残り、同じ日付に同名の行が複数ある場合は別々のToDoとして扱います。GOALS.mdとの連動は最新のTASKS行のIDを明示して設定します。

TASKS.mdのToDo行末にMeryの「日付と時刻」（既定のショートカットは Shift+F5）を追記すると、その時刻を30分単位に丸めてThunderbirdのToDoに時間帯を設定します。予定の日付はタイムスタンプ内の日付ではなく、`TASKS.md` の `## yyyy-MM-dd` 見出しから取ります。開始・終了を両方書く場合は次の形式です。

```markdown
- [ ] 資料整理 10/10/2026 3:07 PM - 10/10/2026 3:42 PM
```

終了時刻を省略した場合は、開始時刻を最寄りの `:00` / `:30` に丸めたうえで30分枠にします。次のTODOの記録時刻から終了時刻を推定しないため、休憩や別作業まで作業時間に含めません。開始・終了を両方書く場合は明記された終了時刻を使い、各時刻を最寄りの `:00` / `:30` に丸めます。丸め後に開始・終了が逆転したり予定が重なったり、30分枠が翌日にまたがったりする場合は同期を止めます。Mery側のタイムスタンプは残り、ThunderbirdのToDo件名からは日時部分を除きます。Meryの記録時刻を正本とするため、Thunderbird側で時刻だけを変更した場合は競合として報告します。

TASKS.mdの項目が `#### グループ名` の下にある場合、見出し名をThunderbird ToDoのカテゴリとして同期します。「今日やるをGeminiでグループ分け」で反映したグループも同じカテゴリになります。分類の正本はTASKS.mdです。

同期はマクロを実行したときに行います。CalDAVサーバーは初回同期でバックグラウンド起動し、Windowsログオン時に自動起動はしません。以前の一方向ICS書き出しファイルは双方向同期には使わないでください。
